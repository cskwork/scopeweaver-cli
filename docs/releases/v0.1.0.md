# scopeweaver-cli v0.1.0 — release draft

First public minor release candidate of the standalone, agent-native ScopeWeaver CLI. Publication is held for unresolved R7 Flash verification, final-head CI and the repository's human review; this file is prepared release copy.

- 297 named operations with JSON output, schema discovery, dry-run and confirmation controls. Each operation has at least one positive functional case in the versioned agent-test ledger; this does not cover every option or state.
- A portable folder containing the CLI and engine. PostgreSQL and required Windows runtime files download with pinned checksums on first use, then remain in the folder. No separate ScopeWeaver/database installation or system service is required.
- Built-in chat, planner and workers through official Codex CLI 0.162.1: ChatGPT OAuth and Z.AI GLM Coding Plan. OAuth, GLM-5.3-Flash and GLM-5.3 completed real tool/worker/finding/report workflows in their recorded candidates. Official Codex and the corresponding login or key are additional requirements; credentials are not bundled.
- Durable chat controls, queue recovery, side questions, compaction, reports, traffic evidence and local integration workflows. Shared engine fixes are proposed separately in [ScopeWeaver PR #38](https://github.com/cskwork/scopeweaver/pull/38).
- English/Korean landing page and documentation, with EN/KO/zh-Hans command interface summaries.

Planned verified artifacts: Windows amd64, Linux amd64 and macOS arm64 ZIPs, plus SHA256SUMS. The native CI workflow snapshots runtime-free packages before first-use testing and retains artifacts only after that job passes. Other build targets are not certified for this release.

Unzip to a writable folder, run `scopeweaver-cli schema --json`, then `scopeweaver-cli health --json` to prepare the local runtime. Stop it before moving the complete folder: `scopeweaver-cli runtime stop --yes --json`. Keep private state out of source control.

Known limits: Windows Unicode paths require usable ASCII 8.3 aliases for PostgreSQL; ASCII paths avoid that requirement. Compaction stores per-call usage without proven inclusion in dashboard aggregates. The rebuilt R7 GLM-5.3/low workflow passed after historical failures. Its zero format-correction attempts establish this workflow pass, not live recovery through the new bounded Z.AI-only correction branch; strict validation remains in place. R7 Flash remains unaccepted: low reasoning produced two findings in its diagnostic run, and high reasoning did not finish the final planner within the unchanged seven-minute task budget. The underlying cause is unknown; the historical R5 Flash pass does not resolve these failures. Integration and update lifecycle fixtures use owned services; they do not prove live-vendor compatibility or a previously published GitHub upgrade. See the [verification record](../CLI-VERIFICATION.md) and [provider guide](../ai-providers.md) for precise versions and evidence.
