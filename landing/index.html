Unpack, discover, and act with zero OS service pollution 운영체제 서비스 등록 없이 압축 해제·탐색·실행

The first operational command downloads and verifies the pinned runtime, initializes private storage in state/, and starts the engine and PostgreSQL. Later commands reuse that runtime. Once setup finishes, core operations need no further dependency downloads. 처음 기능 명령을 실행하면 고정된 런타임을 내려받아 검증하고 state/에 전용 저장소를 만든 뒤 엔진과 PostgreSQL을 시작합니다. 이후에는 같은 런타임을 재사용하며, 코어 실행을 위해 의존성을 다시 내려받을 필요가 없습니다.

Safety Guardrails & Input Contract 안전 장치 및 입출력 규칙

  • Explicit mutation consent (--yes): Reads run directly. Operations that change state, execute tools, contact configured integrations, send notifications, or install updates require --yes. 명시적 변경 승인 (--yes): 조회는 바로 실행됩니다. 상태 변경, 도구 실행, 외부 연동 호출, 알림 전송, 업데이트는 --yes가 필요합니다.
  • Offline validation (--dry-run): Validates and shows a request without starting the runtime. Known credential fields are automatically redacted. 오프라인 사전 검증 (--dry-run): 런타임을 시작하지 않고 요청을 검증·출력하며 알려진 인증 정보 필드는 자동으로 가립니다.
  • Structured payloads: --data @FILE reads a JSON object; --data - reads stdin. Named body flags and repeatable --field key=value support small edits; repeatable --query key=value preserves backend query options. 구조화된 입력: --data @FILE은 JSON 파일, --data -는 표준 입력을 읽습니다. 이름 있는 옵션과 반복 가능한 --field key=value, --query key=value를 지원합니다.
  • No silent overwrites or retries: Downloads require --output and refuse to overwrite existing files. Task submission means acceptance—inspect status, activity, and findings for completion. Uncertain mutations are never auto-retried. 파일 덮어쓰기 및 자동 재시도 금지: 다운로드는 --output이 필수이며 기존 파일을 덮어쓰지 않습니다. 작업 생성 성공은 접수 성공을 뜻하며, 불확실한 변경 요청은 자동 재시도하지 않습니다.
  • Interactive shell (repl): Runs the same command catalog interactively with zero shell command substitution. exit closes the shell; runtime stop --yes stops background work. 대화형 셸 (repl): 셸 명령 치환 없이 동일한 명령을 대화형으로 실행합니다. exit는 셸만 닫고, runtime stop --yes는 백그라운드 작업을 중지합니다.

Exit Codes & Stream Separation 종료 코드 및 스트림 분리 규격

JSON results go to stdout; errors and diagnostics go to stderr. Streaming commands emit one JSON event per line and stop cleanly on Ctrl+C. JSON 결과는 표준 출력(stdout), 오류·진단은 표준 오류(stderr)로 분리됩니다. 스트림 명령은 한 줄에 JSON 이벤트 하나를 출력하고 Ctrl+C로 중지합니다.
